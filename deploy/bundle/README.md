# teleport join bundle

Generated by the gateway (Gateway operations › Modules › teleport › Add).

    docker compose up -d

`private/` holds credentials (the single-use enrolment token, the bundle's
TLS keys); `.env` holds generated passwords; `config.yaml` holds the
event-bus password you gave. Keep them on this host only, and back up the
`teleport-db` and `teleport-state` volumes together: `teleport-state` holds
the mesh identity and, until warden can store secrets for modules, the
management identity files of the registered Teleport clusters
(`/state/credentials`, file mode 0600). The enrolment token is valid for the
lifetime chosen in the wizard; after the first start the module renews its
identity itself.

The module joins the core's event bus (Valkey, TLS) as user `teleport`: the
core's Valkey must accept that user from this host, with access to the
`platform:events:*`, `teleport:lease:*` and `teleport:cache:*` keys. It
calls warden, notification and the scheduler at the addresses you gave; the
scheduler must allow `svc/teleport` to register task types, and its policy
already lets it call `scheduler.v1.TaskExecutor` here (`policy.yaml`).

The module dials each managed Teleport cluster on its proxy address (port
443 or 3080). Private, loopback and link-local addresses are refused unless
`teleport.allowed_private_networks` in `config.yaml` lists the prefix (a
logged opt-out).
